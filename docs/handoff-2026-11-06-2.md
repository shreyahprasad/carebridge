### Approved design (owner, 2026-11-06)

Transportation options are assistance programs, so split by question:

| Stage | Question | Depends on |
|---|---|---|
| Provider match (done) | Which providers fit her? | case |
| Transport benefits (new, rules only) | Which ride/fare programs can she use? | case, not provider |
| Trip plan (new, agent) | How does she get to each pick, and which of her benefits pays? | validated MatchResult + benefits |

Coverage/rights assistance (Alliance, pregnancy Medicaid, minor consent, interpreter rights) is a
later milestone. Do **not** feed assistance back into matching now (owner chose to defer; it only
changes Lucía's coverage tiers and rests on the open asylum-Medicaid question).

1. **Transport benefits, `trip/benefits.py`, app rules, no agent.** One `Predicate`/`decision` per program in
   `data/research/programs.json` with `category == "transportation"` (8 records). Each benefit carries the
   program id, name, how_to_access, phone, source URLs and a "verify before relying" label. Rules from the records:
   - `nemt-amerihealth-caritas-dc`: insurance DC Medicaid and plan "AmeriHealth Caritas DC". Call 1-800-315-3485 at
     least 48 h ahead (routine); no Sunday/holiday rides; loaded SmarTrip option needs 3-5 business days.
   - `nemt-medstar-family-choice-dc`: plan "MedStar Family Choice DC".
   - `nemt-medicaid-ffs`: DC Medicaid with no managed-care plan; book via MTM 3 business days ahead. Alliance does not include it.
   - NEMT (all three) also needs the **provider** enrolled in DC Medicaid. That makes it per-pick: DC provider with
     `accepts_medicaid` = likely; MD/VA = only if `confirm_dc_medicaid` comes back yes (make it a question, not a fact).
   - `wmata-metro-lift`: `snap: true` (both cases are on SNAP, so Lucía qualifies too). 50% off; enroll at wmata.com/metrolift or L'Enfant/Silver Spring/Rosslyn with SmarTrip, EBT card, photo ID.
   - `dc-kids-ride-free`: age 5-21, DC resident, enrolled in a DC school (Lucía yes). The stated purpose is school travel; medical trips are not addressed, so add a question/verify note.
   - `nemt-hscsn`: HSCSN enrollees only (neither case). `wmata-metroaccess` and `transport-dc`: disability-based (neither case; unknown, not eligible).
   - Program data is single-agent research, not independently verified: keep `confidence` and sources on every benefit.
2. **Reachability, app code.** Per pick, from `distance_mi`, `has_car`, `transportation_options`, children/childcare:
   a grade enum, e.g. `walk` (≤1 mi), `one_bus` (≤4 mi), `hard` (≤8 mi), `not_realistic` (>8 mi, or out of state with no
   car and a young child). Thresholds are a design choice: state them in contracts. Today's live run picked Northern
   Virginia Family Services at 9.1 mi for Amina; it should come out `not_realistic`. No live transit routing (brief
   non-goal); any time estimate is labeled an estimate.
3. **Trip-plan agent, `trip/agent.py`, one call, no tools.** Same pattern as `match/agent.py`: `AgentProfile`,
   `RequestOptions(thinking='adaptive', effort='medium')`, closed enums, `validate_output`. Input: the needs profile
   (already scrubbed), picks from the **validated** `MatchResult` (id, name, address, distance, grade, state, tier), and her
   eligible benefit ids. Output per pick: `provider_id`, `grade` (must equal rules), `benefit_ids` (subset of eligible
   **for that pick**), `steps` (booking steps), `tell_client`, `questions` (codes + optional extras). Validator: ids in
   the MatchResult, grade unchanged, benefit ids eligible for that pick, every pick covered once. Unchecked prose is listed
   in `unchecked_fields`.
4. **Combined workflow, `trip/workflow.py` + `python -m trip <case-id> [--live]`.** Calls `run_match` then the trip
   stage with **one shared Budget, one Runtime, one correlation id**. The trip stage reads the match result only through
   `match.models.MatchResult` (`load_match_result` or `model_validate`). Final order: reachability grade then match rank.
   Fallback: rules-only trip plan (grade + benefits, no prose). Output a pydantic `TripPlan` result written to `data/runs/trip/`.
5. **Tests (offline, scripted agent, `tests/test_trip.py`).** Benefits per case (Amina: AmeriHealth NEMT + Metro Lift;
   Lucía: Metro Lift + Kids Ride Free, no NEMT); Virginia pick = not_realistic; NEMT not claimed for an MD/VA pick;
   **invalid-handoff test** (tampered MatchResult with an invented provider id or missing coordinates is rejected and
   the trip agent is never called); trip agent inventing a benefit id or changing a grade → rejected → rules-only;
   one Budget and correlation id across both stages; privacy of the trip task.
6. **Then:** `runtime-check trip`, `sh-code-reviewer`, commit and push to `shreyahprasad`, and give the owner the live line.
   This is the harness "first connected product test": two specialist roles, downstream consumes validated upstream output.

## Provider match, what the next stage can rely on

- `match.workflow.run_match(case, create, model=, live=, runtime=, budget=, correlation_id=, out_dir=, fallback=)` returns a
  validated MatchResult dict; `match.models.load_match_result(path)` reads one.
- Pick fields copied from the provider record: `provider_id, name, address, state, lat, lng, distance_mi, phone,
  intake_phone, website, telehealth`; plus `tier`, `facts[{code,text}]`, `questions[{code,text}]`, `why` (unchecked), `decision`.
- `needs` in the result is the scrubbed profile (no name/phone/address/coordinates/status/plan). The trip stage needs the
  plan name for NEMT, so take it from the trusted `Case`, not from the agent or MatchResult.
- Modes: `live`, `scripted`, `rules_only` (+ `fallback_reason`). Files `<date>-<case>-<mode>-<corr>.json`.
- Contract details: `harness/contracts.md` "Provider match · v1".

## Gotchas learned

- Anthropic API is unreachable from the sandbox; live runs go to the owner's terminal with `!`.
- `git push` needs `github.com` in the Bash call's `allowed_domains`; push with
  `git push https://github.com/shreyahprasad/carebridge.git <branch>` (no `origin` remote). Verify with `git ls-remote`.
- The runtime's output repair prompt is generic ("Return a corrected final JSON value"); the validator's error is not
  sent back, so one repair rarely fixes a semantic error. Fallback handles it.
- `effort='medium'` works with `claude-sonnet-5-5` live (confirmed).
- Pydantic 2.14.3 comes with the Anthropic SDK; no install needed. Models use `extra='forbid'`.
- Earlier gotchas (sandbox `.git/config`/`.claude/` writes, pip SSL, thinking blocks, schema maxLength) are in
  `handoff-2026-11-06.md`.
