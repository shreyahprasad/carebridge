### Design for M8 (proposed 2026-11-06; owner asked for it to be built)

| | |
|---|---|
| **Who calls** | The caseworker phones each provider on the client's behalf. There is also a short ride-booking call script (e.g. AmeriHealth for Amina). |
| **Input** | The validated `TripPlan`, read only through `trip.models.TripPlan` (`model_validate`), plus the validated `MatchResult` and the trusted `Case`. It runs as stage 3 after `trip.workflow.run_workflow`, with the same Runtime, Budget (raise the workflow Budget to 9 requests) and correlation id. |
| **Which providers** | Plans whose grade is not `not_realistic` / `unknown`, in trip order, top 3. |
| **App code (exact, checked)** | **Disclosures:** the client facts the provider may be told come from the Case: age, language and English level, coverage type (and plan name only on the ride call), in-person need, young child or pregnancy when relevant. Each is a closed `Disclosure` enum with app-written text. Her name, phone, address and immigration status are never disclosed and never sent to the agent; the script uses `[client]` and the caseworker supplies the name. **Questions:** every question's text is verbatim rules text, provider-match `questions[].text` plus trip `questions[].text`, keyed by code. Phone numbers come from the provider record and the benefit record. |
| **Agent (one call, no tools)** | Per provider: `opening` (prose), `question_order` (must be exactly the required codes), a short `if_yes` / `if_no` follow-up per code, and `closing` (book the intake, or record the waitlist and the call-back). Plus a `ride_call` script built from the booking notes, if she has an NEMT benefit that is `likely` for a chosen provider. All of this prose is unchecked and listed in `unchecked_fields`. |
| **Guidelines (app-written, part of the contract)** | Fixed rules that the caseworker, and later the M9 call agent, follow: say who is calling and that it is on the client's behalf with her consent; disclose only the listed facts; never give immigration status; if asked for something not listed, say the caseworker will follow up; stop and hand back to a human for anything clinical, legal, a crisis or a payment request; record each answer as `yes` / `no` / `unknown` + note. |
| **Answer slots** | Per question: `{code, answer: null, note: null}`, filled after the call (by the caseworker now, by the call agent later). |
| **Validator** | Only providers from the eligible plans, each covered once; question codes exactly the required set; no digits that look like a phone number, no address and no name in the agent's prose (app code supplies those). |
| **Fallback** | Rules-only script: fixed opening, the exact questions in order, no follow-ups. |
| **Output** | Pydantic `CallScript` (`call-script-v1`) written to `data/runs/script/`. CLI: `python -m script <case> [--live \| --rules-only]` runs all three stages. |
| **Tests** | Offline, scripted agent: invalid handoff (tampered TripPlan, e.g. an invented provider or a changed grade; agent never called); the agent drops a question, invents a provider or writes a phone number → rejected → rules_only; her name and status never reach the agent; one Budget and correlation id across all three stages; not_realistic picks get no script. |

### What the next stage can rely on (TripPlan, `trip-plan-v1`)

- `trip.workflow.run_workflow(case, create, model=, live=, runtime=, budget=, correlation_id=, match_out=, out_dir=)`
  returns `(match, trip)`, both validated dicts; the trip dict may carry `path` (strip it before `model_validate`).
- `plans[]`: `order, match_rank, provider_id, name, address, state, tier, distance_mi, grade, grade_basis,
  time_estimate, benefits[{program_id, use, question}], steps, tell_client, questions[{code, text}], extra_questions`.
  `benefits[]` (case-level): `program_id, name, how_to_access, phone, notes, sources, confidence, verify, decision`.
- Provider call questions are in the MatchResult (`picks[].questions[{code, text}]`); trip questions are in the TripPlan.
  Join them by `provider_id`.
- Contracts: `harness/contracts.md`, "Provider match · v1" and "Transport benefits and trip plan · v1".
- Patterns to copy: `trip/agent.py`, `trip/workflow.py` (`check_handoff`), `trip/scripted.py`
  (`scripted_workflow` dispatches on the system prompt; extend it for the third stage), `tests/test_trip.py`.

## Gotchas learned

- Anthropic API is unreachable from the sandbox; live runs go to the owner's terminal with `!`.
- Push with `git push https://github.com/shreyahprasad/carebridge.git <branch>` and `github.com` in `allowed_domains`.
  Open and merge PRs with the REST API (`gh auth token --user shreyahprasad`, `api.github.com` in `allowed_domains`).
- Result dicts carry `path` after a write; strip it before `model_validate` (`extra='forbid'`).
- Privacy tests: check her exact address string ("3100 block"), not a street name a provider may share.
- Project agents in `carebridge/.claude/agents` aren't available when the session starts in `~/projects/personal`;
  run `sh-code-reviewer` as a general-purpose agent with its instructions.
- The owner's live runs use whatever branch is checked out; check `git branch --show-current` first.
