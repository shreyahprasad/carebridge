---
description: Coordinate a bounded product build with isolated workers and independent evidence
---

Act as the coordinator/integrator. Read the project CLAUDE.md and harness files. User request: $ARGUMENTS

1. Shape: resolve the user, primary workflow, judging rubric, demo outcome, non-goals, constraints and available tools. State assumptions; ask only about decisions that materially block progress. Use the configured sprint timebox, never assume unlimited wall-clock time.
2. Specify: use sh-architect when research is needed. Lock the minimum shared schemas, API examples, errors, design tokens and reference observations in contracts.md. Define measurable task acceptance and verification before implementation. Use /sh-cases when synthetic cases are needed and allowed by the current phase. Avoid adding features to make a spec look ambitious.
3. Bootstrap: for Messages API products, use /sh-messages and the shared guarded runtime; inspect/install the runtime dependency in the project environment and keep product identity/policy separate from Claude Code settings. Establish one runnable end-to-end slice and a startup/check command before broad fan-out. For a multiagent product, follow /sh-messages's connected-test gate: distinct product roles, validated handoffs, shared limits and traceable downstream use. Coding workers and scripted demos do not establish live product-agent execution. Record exact setup, available credentials by name only, versions and any failing baseline checks in progress.md.
4. Plan: populate plan.json with literal write paths, dependencies, owners and acceptance criteria. Validate with the harness CLI described in its README. Only independent ready tasks may run in parallel. Coordinator owns dependency files and shared contracts. Default maximum: three builders; fewer when work is coupled.
5. Build: delegate each ready task to sh-builder with its objective, allowed writes, contract version, context paths, acceptance checks, deadline and return format. Use native worktree isolation in a Git repository with a committed baseline. Do not initialize or commit unrelated user changes. If worktrees are unavailable, use one builder sequentially.
6. Review and integrate: run /sh-review on each proposed result, including sh-code-reviewer and required behavioral checks; verify scope and revision-specific evidence before integrating one result at a time when authorized. Do not merge automatically from worker claims. Run affected checks against the integrated application, not only each branch. Use /sh-pr to write or publish a PR when requested; a passing local review is not merge authorization or remote CI.
7. Evaluate: use sh-verifier on behavior and sh-ui-reviewer on the running interface. A browser owner controls UI testing. Use Chrome for exploration when connected; Playwright tests for reproducible regressions. Evidence must name environment, revision, command, result and artifacts. An inaccessible browser means UI is untested.
8. Repair: dispatch reproducible findings to their owners. Default at most two repair cycles per task, then explicitly replan scope or mark blocked. Never weaken a check merely to pass. Preserve new failures as regression cases.
9. Finish: freeze features before the reserved polish window; run the demo from a clean start, inspect narrow/wide layouts, empty/loading/error states and console errors, and verify the deployment if one is authorized. Report working features, evidence, limitations and the next action.

At checkpoints use /sh-handoff to record completed work, failures, remaining work and next commands in progress.md. Routine worker results stay in progress; session handoffs follow the user's dated handoff convention. Only mark tasks verified after independent checks and review, then use the plan validator to select ready tasks. Resume by rechecking the environment and the last working slice. Stop and replan on contract changes, exhausted timebox or repeated tool failures.

The three-builder cap, two-cycle limit and sprint split are local defaults, not Anthropic prescriptions. Basis: A1–A6, C1–C3; see the source map.
